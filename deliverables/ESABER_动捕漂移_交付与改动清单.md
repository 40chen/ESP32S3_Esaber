## 0. 一句话结论

**"陀螺仪差"只占三分之一。** 模型漂移的主凶是**位置双积分**（模型自己跑飞）和**陀螺量程 ±250dps 削顶**（快挥跟不上/甩过头），次凶是**零偏从未校准**（越放越歪）；**延迟高**的原头号嫌疑"接收端积压"已于 10-06 实物核验**证伪**（您手上的脚本本就正确，见 §3.5），嫌疑转向 **WiFi 链路劣化与设备热降频**；WiFi 省电仍是零成本首查项。其中四项纯软件可修，MPU6050 本身不需要换。

---

## 1. 直接回答您的三个问题

**Q1：是不是陀螺仪差？**
不全是。MPU6050 是无磁力计的老 6 轴（天花板低：yaw 注定缓慢漂移、温漂明显），但把天花板压到地上的是两个软件问题——量程配了 ±250dps（挥剑 500~2000°/s 直接削顶）和位置用加速度双积分（物理上不可行）。**不修这两个，换再好的 IMU 也一样漂。**

**Q2：有没有初始位置校准？**
**没有，一项都没有。** `MotionSensor::begin()`（MotionSensor.cpp L45-55）只做了初始化+量程设置+连接测试+滤波器启动：陀螺零偏校准、初始姿态对齐、位置归零——全都没有。这是"开机就歪、越放越歪"的直接原因。

**Q3：延迟为什么高？**
三个嫌疑环，最大的是**接收端积压**：固件 50Hz 发、Blender 约 24fps 消费，若接收脚本每帧只读一个包且不清缓冲，每秒净积压 26 帧 ≈ **每分钟多 31 秒延迟**。判别指纹：**刚连上跟手、越用越拖 = 积压铁证**；刚连就拖 = 另查（电脑 WiFi 省电/固件节拍）。
**【10-06 实物核验更新】** 您交来的实物脚本已实现"读空缓冲只留最新帧"（ESABER_TICK L83-106）——积压假设**证伪**，"越用越拖"另寻主因，分流见 §3.5。

## 3.5 实物脚本对照结论（10-06 补：您发来的 blender_receiver.py 已核）

**结论：接收端积压嫌疑证伪，"越用越拖"主因不在接收端。**

| 核对项 | 实物脚本现状 | 判定 |
|---|---|---|
| 读空缓冲只留最新帧 | ✅ ESABER_TICK L83-106 `while True` drain-latest | **积压假设证伪** |
| 31B / XOR / 版本 / seq 校验 | ✅ L88-105，与 PROTOCOL.md 一致 | 协议实现正确 |
| 位置通道默认关 | ✅ L22 `APPLY_POSITION=False` | P0-8 实物本就落实 |
| 轴向映射可调 | ✅ L24-26 `AXIS_MAP/AXIS_SIGN`（矩阵基变换，数学精确） | 镜像/恒定偏转可自行校 |
| yaw/位置归零 | ❌ 无 | 参考件 z/p 键可作可选增强 |
| 积压可视化（drain 峰值打印） | ❌ 无（仅丢帧统计） | 诊断台模式仍值得观测一次 |
| 小瑕疵 | L104 丢帧统计：seq 重复时 `(−1) % 256 = 255` 会把计数爆表（UDP 局域网少见，不影响动作、只影响统计准确性） | 可选修 |

实物即 round2 原型（docstring 引用 PROTOCOL.md），核心消费逻辑一直是对的。**P0-7 由"换参考接收端"降级为"可选增强"**（增强项：归零键 / drain 峰值诊断 / Windows ConnectionReset 防护 / selftest）。

**"越用越拖"重新分流，三个候选（按排查成本排序）**：
1. **WiFi 链路劣化**：网卡省电 / 信号随时间衰减——先做 §5 零成本动作；
2. **设备热降频 → 主循环 / IMU 任务饥饿**：越用越热越拖——P0-6 独立任务顺手治它（附赠收益）；
3. **Blender 渲染掉帧**：场景负载型卡顿。

判别指纹升级：**动作滞后越来越厉害但 Blender 帧率正常 → 链路/固件**；**整体越来越卡（帧率掉）→ 渲染负载**。若 1、3 排除后仍拖，抓固件串口日志看遥测 seq 间隔是否随发热劣化。

## 5. 延迟专项 —— 您的电脑端立即可做（零成本）

1. **关 WiFi 网卡省电**：设备管理器 → 无线网卡 → 属性 → 电源管理 → 取消"允许计算机关闭此设备以节约电源"（或电源选项 → 无线适配器设置 → 最高性能）。
2. **跑参考件诊断台观测积压**：`python3 blender_receiver.py --port 5005`，每 2s 打印"单次 drain 峰值包数"，>1 即发生过积压。⚠️ 与 Blender 内直驱脚本**不可同时 bind 5005**（端口冲突/争包），观测时先停 Blender 侧脚本。
3. beacon 结论（已封死）：固件 beacon 恒为默认 100ms，无嫌疑。

## 6. 验收标准（P0 落地后怎么算好）

- 静置 1 分钟：yaw 漂移 **<1~2°/min**（MPU6050 校准后的现实口径，勿按高端 IMU 的 0.1°/min 验收）
- 快挥 10 次：模型全部跟上，无回弹/跳变
- 诊断台：drain 峰值 ≤1、丢帧数不随时间增长
- 位置：默认关闭，跑飞问题消失
